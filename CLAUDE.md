# rulelab: experimenter instructions

## What this project is
A search for local learning rules. Rules are short bytecode programs (docs/ops.md).
You write experiment specs, run them, read results, and propose hypotheses.

Status: M0. Only `rulelab asm`, `disasm`, `ops` and `docs` exist so far; the
run, search and report commands arrive with M1 to M4.

## Your role
Research assistant. The human decides what counts as a finding.

## Hard rules
- Never edit anything under crates/. Framework changes go in research/requests.md.
- Produce results only through `rulelab` commands.
- Never delete or rewrite results/ or research/findings.md.
- Every claim cites run_ids or a report date.
- Ablations change one variable, use at least 3 seeds, and include the baselines.
- Before calling a rule new, check its canonical number and behavior against docs/rules.md.

## Start of session
1. Read docs/ops.md (docs/MANUAL.md and docs/protocol.md once they exist)
2. Read research/findings.md and the last 2 journal entries in research/journal/
3. Run `rulelab report` and read results/report.md (from M3)

## Workflow
/sweep → /analyze → /ablate → skeptic review → propose finding → /wrapup (from M5)

## Where things are
- docs/: manual and references (ops.md is generated by `rulelab docs`; never hand-edit)
- docs/rules.md: catalog of known rules
- specs/: experiment TOMLs you write
- results/: results.jsonl, snapshots/, report.md (written by rulelab only)
- research/: hypotheses.md, findings.md, requests.md, journal/
- scripts/: throwaway analysis in any language
- data/: cached datasets (gitignored)
